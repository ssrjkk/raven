Refusals

What the server refuses to do

Self-hosting is only worth the name if the process says no by itself, with no policy service to consult and nothing to phone home to.

  • Step outside the workspace

    Every file tool resolves its target against the --workspace root with symlinks followed before the check. A path that lands outside is rejected, not clamped to the boundary.

  • Answer an unauthenticated call

    The HTTP transport requires X-Raven-Key or Authorization: Bearer. With no key configured it fails closed: the request is refused rather than waved through.

  • Trust an unknown sender

    The gateway's DM policy defaults to pairing, so a first message from an address it has not paired with gets a code instead of a session. open has to be chosen on purpose.

  • Let an identifier name a path

    Session ids are validated against ^[A-Za-z0-9_-]{1,128}$ at the HTTP, WebSocket, store and CLI boundaries, so one cannot address a directory outside the session root.

  • Hand a key to an export

    Both exporters take --sanitize: ravencode session export --sanitize for a session file, raven backup export --sanitize for the memory tiers. They share one credential definition, so the two cannot drift apart: it masks entries whose names look like credentials and values matching provider key shapes, recursing through nested lists and objects. The memory export marks the file it wrote and raven backup restore refuses a marked one, because restoring masked values would overwrite real memory with ***.

  • Report a number it did not measure

    Nothing here is fetched from a third-party host: the fonts, the tool data and the recorded frames all ship from this directory, and the build fails if a request escapes it.

What never leaves

  • No Raven-operated service. There is no update check, no crash reporter, no analytics beacon and no license ping. Distribution is the repository and its releases, pulled by the operator or by CI — never by the running process.
  • Telemetry is off by default. When switched on it writes to the local database; the analytics and A/B routes serve read queries over the gateway's own authenticated HTTP surface.
  • Provider keys, chats and embeddings stay on the machine. Outbound calls carry only the prompt, query or message the feature was asked to send, to the provider or messenger you configured.
  • Every reachable host is declared. The egress map names each destination and its caller, and a host literal in the code without a row fails the build.
