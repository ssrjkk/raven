Why Raven

Built for control

Your code, your keys, your infrastructure. No cloud dependency, no telemetry, no vendor lock-in.

Self-hosted

One Python process on your own server. No SaaS, no external API calls except the LLM you choose.

66 tools

Files, shell, git, web search, code analysis, testing, memory, routines, monitors — all over MCP.

Two transports

stdio for local clients that spawn the server as a subprocess, JSON-RPC over HTTP for remote access.

Workspace confinement

Every file operation is bounded to your project. Symlinks resolved, escape attempts blocked.

Keyed auth

HTTP transport requires a secret token. Fail-closed: unconfigured means rejected, not accepted.

MIT licensed

Use it, modify it, distribute it. No copyleft, no strings attached.

    Run it

    One registry, three ways in

    The same tools are reachable as an MCP server, as a terminal coding agent with its own session store, and behind a gateway that holds the channel adapters.

    MCP server

    Stdio for a client that spawns the process, JSON-RPC over HTTP for one that reaches it across a network.

    stdio 
    raven-mcp --workspace <dir>
ravencode-mcp --workspace <dir>

    serverInfo.name · raven-mcp / ravencode

    Coding agent

    RavenCode runs the registry in an agent loop, keeps sessions on disk, exports them with credentials stripped and answers as an OpenAI-compatible endpoint.

    cli 
    ravencode tui <dir>
ravencode serve --port 8080
ravencode session export <id>

    sessions under the data dir · basic auth on serve

    Gateway

    One process holds the registry, the DM policy and the messengers, so a chat message reaches the same tools a client frame does.

    cli

raven start --daemon
ravenflow

    15 channel adapters · DM policy pairing|open|closed

    Gateway

    15 channel adapters, one admission policy

    One process holds every messenger on one event loop. Each adapter reads its own variables and stays silent when they are empty, so starting the server without credentials opens no connections and answers no chats.

    How each adapter receives a message
    Adapter Inbound path Variables it reads
    discord Gateway websocket, launched with the bot token DISCORD_BOT_TOKEN
    email IMAP poll of the inbox, SMTP for the reply EMAIL_IMAP_HOST EMAIL_IMAP_USER EMAIL_IMAP_PASS EMAIL_POLL_INTERVAL
    feishu POST /api/webhooks/feishu, SHA-256 over timestamp, nonce, key and body FEISHU_ENCRYPT_KEY
    github POST /api/webhooks/github, HMAC of the raw body in X-Hub-Signature-256 GITHUB_WEBHOOK_SECRET

    matrix GET /_matrix/client/v3/sync long-poll, 30 s MATRIX_HOMESERVER MATRIX_ACCESS_TOKEN

    teams POST /api/webhooks/teams WEB_SECRET_KEY

    A webhook route that has no secret of its own accepts the shared HMAC of the raw body in X-Webhook-Signature instead. With neither key configured it answers 403 to everything: an unverified payload is refused, not parked in a low-priority queue. Outbound-only settings — TEAMS_WEBHOOK_URL, GOOGLECHAT_WEBHOOK_URL, FEISHU_WEBHOOK_URL — carry replies, they do not admit anyone.

    Who may talk to it

    1

    An unknown address opens a pairing, not a session

    reply 
    Welcome! Your pairing code is: `H7KQ2M`
Please send `/pair H7KQ2M` to authorize.

    Six characters from A–Z0–9, minted per address while DM_POLICY=pairing

    2

    The owner approves it on the machine, not in the chat

    cli 
    raven pairing list
raven pairing approve H7KQ2M
raven doctor

    raven doctor lists the adapters that have credentials, so an inert one is visible

    3

    Policy is a switch you throw on purpose

    DM_POLICY=open admits anyone who finds the bot; closed admits only addresses already in the store. CHANNEL_ALLOW_FROM takes a JSON map of channel to user ids and answers a refusal on the spot. Every approval is written to the audit log and counted in the metrics.

    The console the same process serves

    raven start mounts the built React console on the API it already runs — no separate web server, no CDN, no second port to firewall.

    shell 
    cd web && npm install && npm run build
raven start
# http://127.0.0.1:18888 — WEB_HOST, WEB_PORT, RAVEN_WEB_DIST

    Bound to loopback by default; the gateway warns when you point WEB_HOST at 0.0.0.0. The bundle is looked up in RAVEN_WEB_DIST, then the wheel, then web/dist, and if none of them carry an index.html the API still starts and logs the build command instead.

    Refusals

    What the server refuses to do

    Self-hosting is only worth the name if the process says no by itself, with no policy service to consult and nothing to phone home to.

    • Step outside the workspace

      Every file tool resolves its target against the --workspace root with symlinks followed before the check. A path that lands outside is rejected, not clamped to the boundary.

    • Answer an unauthenticated call

      The HTTP transport requires X-Raven-Key or Authorization: Bearer. With no key configured it fails closed: the request is refused rather than waved through.

    • Trust an unknown sender

      The gateway's DM policy defaults to pairing, so a first message from an address it has not paired with gets a code instead of a session. open has to be chosen on purpose.

    • Let an identifier name a path

      Session ids are validated against ^[A-Za-z0-9_-]{1,128}$ at the HTTP, WebSocket, store and CLI boundaries, so one cannot address a directory outside the session root.

    • Hand a key to an export

      session export --sanitize masks entries whose names look like credentials and values that match provider key shapes, recursing through nested lists and objects.

    • Report a number it did not measure

      Nothing here is fetched from a third-party host: the fonts, the tool data and the recorded frames all ship from this directory, and the build fails if a request escapes it.

    Setup

    Install and configure

    Three steps from a clone to a client calling tools.

    1

    Install the server

    shell 
    git clone https://github.com/ssrjkk/raven
cd raven
pip install .

    Python 3.11+ · installs the raven-mcp and ravencode-mcp commands

    2

    Add it to your client

    json 
    {
  "mcpServers": {
    "raven": {
      "command": "raven-mcp",
      "args": ["--workspace", "/path/to/project"]
    }
  }
}

    Same shape for every MCP client that starts a stdio server

    3

    Call the tools

    Ask the assistant to read a file, run a command or search the web. It calls the MCP tool and Raven runs it inside the workspace you allowed. Over HTTP, the same tools answer POST /mcp/rpc with a bearer key.
