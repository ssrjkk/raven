Setup

Install and configure

Three steps from a clone to a client calling tools.

1

Install the server

shell 
git clone https://github.com/ssrjkk/raven
cd raven
pip install .

Python 3.11+ · installs the five commands, raven-mcp and ravencode-mcp among them · what the optional groups add

2

Add it to your client

json 
{
  "mcpServers": {
    "raven": {
      "command": "raven-mcp",
      "args": ["--workspace", "/path/to/project"]
    }
  }
}

Same shape for every MCP client that starts a stdio server

3

Call the tools

Ask the assistant to read a file, run a command or search the web. It calls the MCP tool and Raven runs it inside the workspace you allowed. Over HTTP, the same tools answer POST /mcp/rpc with a bearer key.

Install the extras you actually use

The base install runs the gateway, the tools and the console. Everything that talks to another system lives in optional groups, and a group you did not install is not an error message — it is a feature that stopped running. Install what you use: pip install -e ".[voice,speaker]".

A control that cannot run now says so instead of passing quietly: voice_verify answers Anti-spoof: NOT evaluated and /api/voice/verify returns anti_spoof_checked: false when speaker is missing, and a build that ships an import no group declares fails tests/test_dependency_declarations.py.

Run the gateway

The same install also starts the gateway — the process that holds the channel adapters, the DM policy and the web console.

shell 
raven start
raven start --daemon
ravenflow
raven doctor

raven doctor names the adapters that have credentials and the ones that would stay silent, so a misconfigured channel is visible before the first message. Configuration lives in .env; .env.example documents every variable.
