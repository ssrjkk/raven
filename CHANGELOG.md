Handles now open with `isolation_level=None`, so a write is durable when it runs instead of waiting for whichever caller reaches `commit()` first — Python 3.12 rolls pending work back on close, which is where those writes used to go — `transaction()` takes a per-handle write gate, issues `BEGIN IMMEDIATE`, re-enters through a SAVEPOINT and owns the commit, and every other statement waits. `run_script()` carried the other half of the lie: `executescript` commits whatever transaction is open before it runs, so the "one transaction per migration batch" at `migrations.py:472` and `:513` never held (`tables after the rollback: ['seed', 't1']`) and a failing migration left its schema behind with no version row; inside a transaction a script is now cut with `sqlite3.complete_statement` and executed statement by statement, which keeps quoted semicolons and trigger bodies in one piece. `PostgresDB._tx` was instance state, so a concurrent task's `execute()` silently joined another task's transaction and was rolled back by it; it is a per-handle `ContextVar` now. `tests/core/test_asyncdb_transactions.py` pins each of these.
